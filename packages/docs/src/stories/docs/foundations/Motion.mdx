export const DurationBar = ({ token, cycle = 1500 }) => {
  const [key, setKey] = useState(0)
  useEffect(() => {
    const id = setInterval(() => setKey((k) => k + 1), cycle)
    return () => clearInterval(id)
  }, [cycle])
  return (
    <div
      style={{
        position: 'relative',
        height: '6px',
        borderRadius: '999px',
        background: 'var(--morphink-color-muted)',
        overflow: 'hidden',
      }}
    >
      <div
        key={key}
        style={{
          position: 'absolute',
          top: 0,
          left: 0,
          height: '100%',
          width: '40px',
          borderRadius: '999px',
          background: 'var(--morphink-color-accent)',
          animation: `motionSlide var(${token}) ease-in-out forwards`,
        }}
      />
    </div>
  )
}

## Overview

morphink uses token-based motion to ensure consistent, accessible animation. Duration and easing primitives combine into **motion shorthands** that are applied across all components.

**Principle**: Animations should feel responsive and purposeful, never decorative.

---

## Animation Shorthands

Pre-composed `duration + easing` variables for **keyframe animations** (`animate-[]`).
These combine non-obvious easing curves so you don't have to remember them.

## Accessibility

morphink uses a **token-based** approach to `prefers-reduced-motion`:

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --morphink-duration-fast: 0ms;
    --morphink-duration-normal: 0ms;
    --morphink-duration-slow: 0ms;
    --morphink-duration-slower: 0ms;
  }
}
```

All duration tokens become `0ms`, which instantly collapses every transition and animation that references them. No per-component overrides needed.

---

## Design Principles

- **Enter > Leave**: Entrances should be slower (300ms) and more deliberate; exits should be faster (200ms) and less attention-grabbing.
- **Keyframes are free, timing is shared**: Each component defines its own visual motion (scale, translate, stroke...) but uses shared duration/easing tokens to keep the system feeling cohesive.
- **Spatial vs Effects**: Position/size changes (spatial) can use overshoot (spring). Color/opacity changes (effects) should not overshoot.
- Avoid pure decorative animation. Every motion should communicate a state change or guide the user's attention.
